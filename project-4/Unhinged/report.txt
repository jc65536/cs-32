Performance/design bugs I haven't been able to squash:

- My code uses 4x as much memory as the sample program

- Due to my design of RadixTree, where nodes live in a linked list and contain
pointers to its children (who live in the same linked list), a shallow copy does
not suffice to create an independent copy of the RadixTree. Because I sometimes
need to insert a RadixTree (e.g. within a PersonProfile) into a RadixTree, this
can lead to use-after-free errors. That's why my implementation of
SharedPersonProfile contains a resetTree() function to correct the pointers
after a copy. Even though this design is janky, it was easier than writing a
proper copy assignment operator.

    RadixTree<int> rt;
